# LAB-004 – Reverse Proxy Foundation

## Objective

Replace direct LAN exposure of Docker services with a centralized reverse proxy architecture using Caddy.

---

## Success Criteria

- Homepage accessible via home.yerigan.home.arpa
- Uptime Kuma accessible via status.yerigan.home.arpa
- Pi-hole accessible via dns.yerigan.home.arpa
- Portainer accessible via portainer.yerigan.home.arpa
- Services communicate over the Docker proxy network.
- Direct host web ports removed.
- Caddy becomes the single web entry point.

## Lessons Learned

- Reverse proxies provide abstraction between users and services.
- Docker's internal DNS eliminates the need for static container IPs.
- Shared Docker networks allow secure service-to-service communication.
- User-facing URLs remain stable even when backend infrastructure changes.
- Monitoring should use internal service names whenever possible.
