# LAB-005 — Home Assistant Platform Foundation

**Status:** In Progress  
**Date Opened:** August 5, 2026  
**Owner:** Randall Yerigan  
**Priority:** High  
**Category:** Family Platform / Infrastructure / IoT

## Business and Family Value

Establish a centralized, transferable smart-home platform that consolidates devices from multiple vendors while prioritizing local control, security, reliability, and minimal subscription dependence.

The platform should provide tangible household value while developing reusable IoT architecture, automation, networking, and security skills applicable to future professional and service-provider work.

## Objective

Deploy Home Assistant as the central automation and integration platform for the Yerigan Home Platform.

The initial implementation will establish the platform only. Device migrations and production automations will be introduced incrementally after the foundation is validated.

## Design Requirements

1. Local-first operation whenever technically practical.
2. No subscription requirement unless a clear benefit justifies it.
3. One primary family-facing interface.
4. Vendor ecosystems should integrate through Home Assistant rather than dictate the architecture.
5. Basic household functions must retain manual controls.
6. Important automations should continue during Internet outages whenever possible.
7. The platform must be transferable to the new house.
8. Configuration and deployment definitions must be documented and version controlled.
9. Persistent Home Assistant data must be backed up.
10. Device onboarding must occur incrementally with validation after each integration.
11. Security and network segmentation must be considered before large-scale IoT deployment.
12. Family usability and reliability take priority over technically impressive but fragile automations.

 ## Lessons Learned

- Host networking allows Home Assistant to participate directly in LAN discovery protocols.
- Validate each infrastructure layer independently before changing configuration.
- HTTP 400 errors from Home Assistant behind a reverse proxy may indicate forwarded-header trust issues.
- Current Home Assistant versions migrate portions of HTTP configuration into `.storage`, making that the active configuration source after first-run setup.
- Evidence should drive troubleshooting rather than assumptions.
