# LAB-010 — Infrastructure Observability and Monitoring

## Objective

Establish centralized infrastructure observability for the Yerigan Labs Ubuntu platform so host and container health can be measured historically, visualized, evaluated against defined thresholds, and escalated through mobile notifications.

The lab is intended to move Yerigan Labs beyond simple service availability monitoring toward health and performance monitoring.

## Business and Operational Value

A service being available does not necessarily mean the underlying platform is healthy.

LAB-010 provides visibility into resource conditions that may indicate developing failures before users experience an outage.

The monitoring architecture also provides historical telemetry that can support troubleshooting, capacity planning, incident investigation, and future security monitoring.

## Architecture

The monitoring pipeline separates responsibilities between components:

- Node Exporter collects Ubuntu host metrics.
- cAdvisor collects container metrics.
- Prometheus stores and queries time-series telemetry.
- Grafana provides visualization and alert evaluation.
- Caddy provides controlled access and internal routing.
- Home Assistant provides selected mobile notification delivery.

This architecture uses separation of concerns rather than relying on a single monitoring component to perform every function.

## Core Host Metrics

The initial host-health dashboard includes:

- CPU utilization
- Memory utilization
- Root filesystem utilization
- Network throughput on `ens18`
- Host uptime

## Alerting Policy

Initial production alerting was implemented for root filesystem utilization.

### Warning

- Root filesystem utilization greater than 85%
- Condition must persist for 10 minutes
- Severity: `warning`
- Service: `ubuntu`
- Category: `capacity`

### Critical

- Root filesystem utilization greater than 90%
- Condition must persist for 5 minutes
- Severity: `critical`
- Service: `ubuntu`
- Category: `capacity`

Higher-severity conditions use a shorter acceptable duration because the remaining operational margin and corresponding risk are greater.

## Notification Path

Selected infrastructure alerts follow this path:

Grafana → Caddy → Home Assistant → Mobile Notification

Grafana remains responsible for detection and classification.

Home Assistant provides notification orchestration and mobile delivery.

## Validation

Prometheus successfully collected Node Exporter and cAdvisor metrics.

Grafana successfully queried Prometheus and displayed host telemetry.

A controlled root-filesystem warning test validated the alert lifecycle:

Normal → Pending → Firing

The alert was successfully delivered through the configured Grafana contact point, Caddy, Home Assistant, and the administrator's mobile device.

The production warning threshold was restored following testing.

## Operational Finding

During initial dashboard implementation, root filesystem utilization was observed at approximately 99%.

Independent validation showed:

- Root filesystem size: approximately 19 GB
- Used capacity: approximately 18 GB
- Available capacity: approximately 230 MB
- Inode utilization: approximately 34%

Investigation showed the Ubuntu LVM volume group contained approximately 19 GB of unused capacity.

The root logical volume was expanded by 10 GB while retaining approximately 9 GB of unallocated volume-group capacity for future requirements.

Following remediation, Grafana reported root filesystem utilization of approximately 66%.

This demonstrated that service availability alone was insufficient to identify the developing capacity condition.

## Monitoring Philosophy

Monitoring does not automatically imply remediation.

For unexpected infrastructure conditions, the preferred initial workflow is:

Detect → Alert → Preserve Evidence → Investigate → Remediate → Validate

Automated remediation may be considered later for well-understood failure conditions where the corrective action is predictable and evidence preservation requirements are addressed.

## Result

LAB-010 established the Yerigan Labs observability foundation and validated one complete production alert path from infrastructure telemetry through administrator mobile notification.

Additional alert types, centralized logging, security monitoring, automated incident-context capture, and automated remediation are intentionally outside the scope of LAB-010 and should be implemented as separate future work.
