## Interview Questions

### Why did you choose this approach?

I wanted version control established before the infrastructure became more complex so configuration and documentation changes would have history, rollback context, and an off-host copy.

### What would you do differently in a production enterprise environment?

I would add formal branch protections, peer review, CI validation, secrets scanning, access governance, repository ownership standards, and automated deployment controls appropriate to the environment.

### What did you learn from the project?

Version control becomes much more valuable when introduced before configuration sprawl occurs rather than after the environment has already become difficult to reconstruct.

### What was the biggest technical or operational risk?

At this stage, the larger risk was configuration and documentation existing only locally without a reliable version-controlled remote copy.
